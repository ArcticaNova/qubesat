# Comms / FSM changes — 2026-09-30

Context: the HopeRF radio was moved from the Radio 2 footprint to the Radio 1 footprint
on the PyCubed v05 (CircuitPython 8.2.10). `lib/pycubed.py` on the board already uses the
`RF1_*` pins, so no library changes were needed. The radio initializes at 433 MHz with
these settings (probe test passed).

The board's previous contents (496 MHz test `Comms.py`, `main.py`, `receive.py`,
`radio_util/`, `lib/`) are backed up in `2026-09-30_old_pycubed_code/`.

## Comms.py

### NVM moved to bytes 20–26 (was 12–18)
`pycubed.py` stores its own flags in NVM byte 16 (low battery, solar, GPS bits), and our
`rx_ticks` config was overwriting it. pycubed.py uses bytes 0, 6, 7, 9, 10, 11 and 16.

| Byte | Contents |
|---|---|
| 20–22 | three copies of the state code |
| 23 | state checksum |
| 24 / 25 / 26 | rx_ticks / tx_packet_count / telem_cadence |

### Fresh NVM reads as 0xFF, now treated as "unset"
On this board, unwritten NVM bytes read **255**, not 0. `CommsConfig` now falls back to
the defaults for both 0 and 0xFF (50 RX ticks ≈ 10 s, 10 packets per TX window, beacon
every 3rd window). Before this change, a fresh board would have listened for 255 ticks
(≈ 50 s) per window.

### On-air packets now match our packet layout exactly (TinyGS fix)
`pycubed_rfm9x.send()` always adds a 4-byte RadioHead header in front of the data
(destination, node, identifier, flags). TinyGS was therefore receiving 20-byte beacons,
and `tinygs_decoder.py` rejects anything that isn't 16 bytes.

- New `send_raw(radio, packet)` passes the first 4 bytes of our packet as the RadioHead
  header fields, so the bytes on air are exactly our packet. `CommsManager` uses it for
  every transmit. Packets shorter than 5 bytes are zero-padded, because the driver needs
  at least 1 byte after the header.
- Receiving now uses `receive(..., with_header=True)`, so we get the full on-air bytes and
  the `0xC0` / `0xA0` header byte is at index 0.

**Ground station impact:** if the ground station uses `pycubed_rfm9x` (or `adafruit_rfm9x`),
send uplink commands with `Comms.send_raw(radio, Comms.build_state_command(...))`, not
`radio.send(...)`. Otherwise the satellite will see 4 extra header bytes and ignore the
command.

### Sync word and `node` fixed
`r.node = 0x12` did not set the sync word. `node` is a RadioHead address filter, so it
made the radio drop any packet not addressed to 0x12.

- The sync word is now written directly to the SX127x register (`0x39 = 0x12`, the LoRa
  public sync word that TinyGS uses).
- `node` is set to `0xFF` (broadcast), so the radio accepts every packet. Comms filters
  packets itself by header byte.

### Beacon tolerates missing sensors
`pycubed.py` returns `None` (it doesn't raise) when a sensor is down. `cubesat.temperature`
is `None` whenever the IMU fails. `int(None)` in `build_beacon_packet` raised an
exception that reached the FSM's fatal handler, so every beacon reset the board.

`build_beacon_packet` now accepts `None` and encodes it as "unknown":

| Field | Unknown value |
|---|---|
| battery | `0` mV |
| temperature | `0xFF` |

Valid temperatures are capped at 214 °C (raw 254) so they can't collide with `0xFF`.

## QubeSatFSM.py

- **Solar panel check:** `cubesat.charging_current` doesn't exist in pycubed.py; the
  correct call is `cubesat.charge_current()`. It is a method, and it returns **mA**. The
  check previously failed every time.
- **Beacon / battery check:** if a sensor is missing, `None` is passed through as
  "unknown" instead of defaulting to 0. The battery check skips the reading instead of
  crashing on `None`.
- **SD card:** `cubesat.new_file()` returns `None` (it doesn't raise) when there's no SD
  card. Without an SD card, `sd_card_initialized` was still being set to True, so the FSM
  moved on to SCIENCE. It now counts as a failed init.

## tinygs_decoder.py

Decodes the new "unknown" values: battery `0` and temperature `0xFF` both become `None`.
**Resubmit this file to TinyGS** if it has already been submitted.

## Testing

- **On the board (before these fixes):** probe test passed. Also confirmed: `aesio` is
  available (real AES, not the XOR fallback), NVM is 8192 bytes, and NVM bytes 20–26 read
  255.
- **On a Mac, with a fake radio that copies `pycubed_rfm9x`'s header add/strip/filter
  behaviour:**
  - the beacon is exactly 16 bytes on air and decodes correctly, both with sensors present
    and with sensors `None`;
  - a state command sent from the ground with `send_raw` is received, verified and applied;
  - fresh 0xFF NVM gives the default schedule.
- These checks are saved in `unit_tests/test_newcode_comms.py`. Run them from the repo
  root with `python3 -m unittest unit_tests.test_newcode_comms -v`.
- **Not yet run on the board:** `send_raw`, the sync-word register write, and receiving
  with `with_header=True` (the board was unplugged).

## Not changed (on hold)

- `BurnWire.py`: still fires on import; duty cycle and duration don't match how the FSM
  calls it.
- `Task.py`: tasks with `schedule_later=True` never run.
